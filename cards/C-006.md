# C-006 — Isolation Forest anomaly context

status: done
deps: C-004, C-005
implements: FR6
risk: standard
risk-reason: A model trained on too little or noisy data can create false alarms; it must remain advisory with warm-up/unknown behavior.
risk-ack: none

## Scope

Add one offline/warm-up Isolation Forest detector over the contract feature vector (bpm, FPS, amplitude, regularity, quality score), persist/reload the local model, and attach normal, anomaly, or unknown plus score to each measurement. The detector never suppresses threshold alerts and returns unknown when baseline/model data is insufficient.

## Independent test

The caregiver can open the dashboard/history and see whether each eligible block is normal, anomalous, or not yet classifiable, with the feature/model reason visible in the detail state.
