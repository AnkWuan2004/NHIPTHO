# C-005 — Unified threshold alerts and email history

status: done
deps: C-003, C-004
implements: FR5
risk: standard
risk-reason: Alerting can create harmful noise or silently fail; it touches email credentials and user-visible warning behavior.
risk-ack: none

## Scope

Unify low/high threshold policy around defaults `<5` and `>25`, add caregiver-readable threshold settings, persist alert records, apply consecutive-reading/cooldown behavior, and make SMTP success/failure observable. Keep measurement persistence independent from email delivery and do not add Telegram.

## Independent test

The caregiver can see one alert in alert history and receive one email for a threshold breach; repeated readings during cooldown do not create duplicate emails, and SMTP failure remains visible without losing the measurement.

`backend/app.py`, `backend/config.py`, `backend/models.py`, `backend/alarm_manager.py`, `backend/email_sender.py`, `dashboard/templates/index.html`, `dashboard/static/js/dashboard.js`
