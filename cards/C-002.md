# C-002 — Local caregiver authentication

status: done
deps: C-001
implements: FR3
risk: security-class
risk-reason: Authentication protects local measurement data and is security-class even though deployment is local.
risk-ack: none

## Scope

Implement one caregiver account provisioned from environment/setup values, password hashing, login/logout/session checks, `/api/me`, and a Vietnamese login page. Protect `/` and all caregiver data routes according to the contract; do not add registration, roles, or password reset.

## Independent test

The caregiver can open `/login`, submit valid credentials, reach the dashboard route, log out, and is redirected/denied after logout; invalid credentials never reveal data.

## Allowed files

`backend/app.py`, `backend/auth.py`, `backend/config.py`, `backend/models.py`, `backend/init_db.py`, `dashboard/templates/login.html`, `dashboard/static/css/style.css`

## Verify (run these before calling the card done)

- [x] `curl -i http://127.0.0.1:5000/login`; returned HTTP 200 and rendered the Vietnamese caregiver login form.
- [x] Wrong credentials with a cookie jar returned HTTP 401; unauthenticated `/api/latest` returned HTTP 401.
- [x] Correct login returned HTTP 200, `/api/me` returned authenticated caregiver, dashboard returned HTTP 200, logout returned HTTP 200, and `/api/me` afterward returned HTTP 401.

## Done-evidence (world-state proof, named BEFORE building)

At `http://127.0.0.1:5000/login`, a real browser/curl session demonstrates successful login, protected route access, logout, and denial afterward.

## Evidence (paste the actual proof here when done)

`py_compile` passed for all changed Python files. With `CAREGIVER_USERNAME=caregiver CAREGIVER_PASSWORD=demo-password`, `backend/init_db.py` created/confirmed the hashed caregiver account and the local Flask server was exercised at `http://127.0.0.1:5000`:

```text
root_without_auth=302 http://127.0.0.1:5000/login?next=/
login_page=200
api_without_auth=401
wrong_login=401
correct_login=200
me_after_login=200
dashboard_after_login=200
logout=200
me_after_logout=401
```

Response bodies confirmed `INVALID_CREDENTIALS`, `{"authenticated":true,"username":"caregiver"}`, and `AUTH_REQUIRED` after logout. No plaintext password is stored in the account model; it uses Werkzeug password hashing.
